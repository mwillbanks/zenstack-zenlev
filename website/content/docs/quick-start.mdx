## Install

Use Bun 1.4.4 or later in a ZenStack V3 project.

```sh
bun add -d @mwillbanks/zenstack-zenlev
```

Keep the project's ZenStack ORM and Kysely versions compatible with the package peer dependencies.

## Connect the client

Create `zenlev.config.ts` beside your project package manifest.

```ts
import { defineConfig } from '@mwillbanks/zenstack-zenlev'
import { db } from './db'

export default defineConfig({
  client: db,
  migrationsDir: 'migrations',
})
```

Zenlev borrows this client. Your application owns its lifecycle. Use an [owned factory](./configuration) when the CLI should close connections itself.

## Create the migration

```sh
bunx zenlev migrate create --name add_categories --namespace predeploy --empty
```

Open the generated file. Keep its generated ID and creation timestamp. Implement `up` and, when reversible, `down`.

```ts
import type { MigrationCtx } from '@mwillbanks/zenstack-zenlev'

export async function up(ctx: MigrationCtx) {
  await ctx.db.schema
    .createTable('categories')
    .addColumn('id', 'integer', (column) => column.primaryKey())
    .addColumn('name', 'text', (column) => column.notNull())
    .execute()
}

export async function down(ctx: MigrationCtx) {
  await ctx.db.schema.dropTable('categories').execute()
}
```

Keep the generated `meta` export in the same file. Commit reviewed migration files through your normal project workflow.

## Inspect and apply

```sh
bunx zenlev migrate status
bunx zenlev migrate apply --namespace predeploy --plan-only
bunx zenlev migrate apply --namespace predeploy
bunx zenlev migrate tree --show-supersedes
```

A plan reports pending prerequisites outside the selected namespace. Apply those stages before retrying.

Use [bootstrap and cutover](./adoption) to prepare a new database or adopt an existing Prisma-managed database.
