---
title: 'SQL object security'
description: 'Check invoker or definer mode and trusted routine search paths.'
---

Uses security attributes visible in source or catalogs for applicable routines, views, triggers, and events.

Enable this opt-in rule under `lint.rules`.

## Configuration

```ts
import { defineConfig } from '@mwillbanks/zenstack-zenlev'

export default defineConfig({
  lint: {
    rules: {
      'zenlev/objects/security': [
        'error',
        {
          kinds: ['function', 'procedure'],
          trustedSearchPath: ['pg_catalog', 'app', 'pg_temp'],
        },
      ],
    },
  },
})
```

## Parameters

- `security` requires `invoker` or `definer` where the attribute is available.
- `trustedSearchPath` permits a list of PostgreSQL schemas. A definer routine needs an explicit nonempty path containing only those schemas.
- `publicExecute: false` requests a coverage warning because grant and role metadata are needed to establish PUBLIC EXECUTE access.

All built-in rules accept the [shared selectors](./reference/lint-rules#shared-selectors).

## Example

A PostgreSQL `SECURITY DEFINER` routine can use `SET search_path TO pg_catalog, app, pg_temp` when the schemas are trusted in that deployment.
