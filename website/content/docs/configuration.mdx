title: 'Configuration'
description: 'Choose project paths, environments, stores, and client ownership.'
---

Configuration precedence follows CLI flags, dedicated configuration, the `zenlev` package.json key, and defaults.

Supported dedicated files are `zenlev.config.ts`, `zenlev.config.js`, and `zenlev.config.json`.

## Environment-aware client factory

```ts
import { defineConfig } from '@mwillbanks/zenstack-zenlev'
import { createClientForEnvironment } from './db'

export default defineConfig({
  createClient: async ({ name, cwd }) => {
    const client = await createClientForEnvironment(name, cwd)
    return {
      client,
      dispose: () => client.$disconnect(),
    }
  },
  migrationsDir: 'migrations',
  hashing: { algorithm: 'sha256', normalizeLineEndings: true },
})
```

The factory receives the effective environment and working directory. Select them with `--env` and `--cwd`. Zenlev does not mutate process globals to select a connection.

Choose one connection source per configuration. A supplied client is borrowed. A factory explicitly returns its disposer.

## JSON configuration

Reference a project module when JSON cannot hold the client factory.

```json
{
  "migrationsDir": "migrations",
  "clientModule": "./zenlev-client.ts"
}
```

Export the factory from the referenced module as its default export. Module references resolve relative to the declaring configuration file. Migration paths resolve relative to the effective project working directory.

## Store location

| Dialect    | Default           |
| ---------- | ----------------- |
| PostgreSQL | `zenlev` schema   |
| MySQL      | `zenlev` database |
| SQLite     | `zenlev_` tables  |

The connection must have permission to create and access the chosen store. A permission failure stops execution.

Use `store.location: 'table'` and explicit table names when a separate namespace is unsuitable. Keep each environment's store configuration stable after its first run.
