Run `zenlev --help` and command-specific help for the installed version's complete options.

## Schema work

| Command                                    | Purpose                                         |
| ------------------------------------------ | ----------------------------------------------- |
| `db push --dry-run --sql`                  | Inspect schema changes and SQL                  |
| `db push --create-migration --name <name>` | Generate a migration from the schema comparison |
| `db push`                                  | Apply the reviewed schema change set            |

Use `zen db pull` to introspect the database into ZModel.

## Migration work

| Command                                     | Purpose                                          |
| ------------------------------------------- | ------------------------------------------------ |
| `migrate create --name <name> --empty`      | Create a TypeScript migration                    |
| `migrate apply --plan-only`                 | Inspect the selected graph                       |
| `migrate apply`                             | Execute the selected migrations                  |
| `migrate status`                            | Inspect stored and local migration state         |
| `migrate tree`                              | Print the dependency graph                       |
| `migrate rollback --id <id> --cascade`      | Generate dependent-first compensation            |
| `migrate rollback --id <id> --compensate`   | Generate compensation for one target             |
| `migrate remove --id <id> --dry-run`        | Preview removal of an unapplied migration        |
| `migrate resolve --id <id> --hash <hash>`   | Accept a changed migration hash                  |
| `migrate reshape --id <id> --accept <hash>` | Add an accepted alternative hash                 |
| `migrate recover`                           | Reconcile inspected attempts and abandoned locks |

Real removal requires a configured database so Zenlev can protect recorded migrations. An offline preview can check the local graph.

## Automation

Use `--json` for machine output. Use explicit drop decisions in noninteractive schema operations.

```sh
bunx zenlev migrate status --json
bunx zenlev db push --drop-missing-tables=skip
```

`--dry-run` and `--plan-only` inspect work without calling migration handlers or initializing the ledger.
