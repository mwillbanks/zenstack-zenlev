---
title: 'Dependency graph'
description: 'Select deployment stages while preserving prerequisites.'
---

`dependsOn` forms a directed graph. Every referenced ID must exist locally or in stored history. The effective graph must remain acyclic after supersedes rewriting.

## Selection

```sh
bunx zenlev migrate apply --namespace predeploy --plan-only
bunx zenlev migrate apply --only <id>,<id> --plan-only
bunx zenlev migrate apply --from <id> --to <id> --plan-only
bunx zenlev migrate tree --format mermaid --show-supersedes
```

`--from` includes the selected migration and its descendants. `--to` includes the selected migration and its ancestors. These bounds intersect namespace, tag, and explicit-ID filters.

Pending dependencies outside the selection block execution. Namespace selection keeps deployment stages explicit.

## Deterministic order

Independent nodes use lexical ID order. Superseding migrations replace future graph edges without rewriting the historical record. Creation time chooses among competing superseders, followed by lexical ID for equal timestamps.

## Cross-namespace deployments

A `postdeploy` migration can be a prerequisite for a later `predeploy` migration. Inspect each deployment's plan. An unapplied prerequisite can prevent a stage from running even when its own namespace matches.
