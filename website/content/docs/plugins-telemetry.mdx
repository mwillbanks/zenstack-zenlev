## Lifecycle plugins

Plugins register lifecycle hooks during setup. They can decorate context with static values and derive values per invocation.

```ts
import { definePlugin } from '@mwillbanks/zenstack-zenlev'

export const auditPlugin = definePlugin({
  name: 'audit',
  decorate: { deploymentId: 'deployment-42' },
  derive: (ctx) => ({ auditId: `${ctx.deploymentId}:${ctx.env.name}` }),
  setup(api) {
    api.onBeforeMigration((ctx, meta) => {
      ctx.reporter.event('migration.reviewed', {
        'zenlev.migration.id': meta.id,
        status: 'reviewed',
      })
    })
  },
})
```

`definePlugin` infers decorated and derived context types for hooks. Derived values are recomputed for each command context. Register plugins through the `plugins` configuration option. Hooks run in registration order. Context decorations must use unique keys.

Lifecycle hooks cover initialization, commands, plans, migrations, warnings, errors, and store reads and writes. A before hook can return `false` to abort. A replacement plan must still satisfy graph and integrity rules.

## OpenTelemetry

Telemetry is disabled by default.

```ts
import { defineConfig } from '@mwillbanks/zenstack-zenlev'
import { db } from './db'

export default defineConfig({
  client: db,
  telemetry: {
    opentelemetry: {
      enabled: true,
      serviceName: 'deployment-migrations',
      exporter: 'otlp',
      otlpEndpoint: 'http://localhost:4318/v1/traces',
    },
  },
})
```

Choose `exporter: 'console'` for local inspection; it writes JSON spans to stderr. Enabling telemetry without specifying an exporter also selects console. The default service name is `zenlev`. Close the Zenlev service so exporters flush and shut down.

The built-in reporter only exports `code`, `status`, `durationMs`, and `zenlev.migration.id` attributes. Values must be finite numbers, booleans, or short identifier strings. Other attributes are discarded, including custom `auditId` values. Credentials, SQL parameter values, migration data, and exception messages are excluded. Custom reporters remain responsible for their own data handling.

## Warning coverage

Schema comparison identifies known drops, narrowing changes, and constraint risks. Kysely operations can expose additional warnings during execution.

Arbitrary TypeScript and raw SQL can perform effects that automatic detection cannot infer. Declare warnings in migration metadata and review external side effects manually.
